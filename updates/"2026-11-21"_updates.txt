    Fix NoMethodError on unhandled response in jupyter_login
    
    In auxiliary/scanner/http/jupyter_login, requires_password? queries the
    Jupyter /tree endpoint. If the request times out or the connection resets,
    send_request_cgi returns nil. The existing check only guarded the status code
    (res&.code == 200), allowing execution to fall through to res.headers and
    raising NoMethodError: undefined method 'headers' for nil:NilClass.
    
    Additionally, if the response is a redirect without a Location header, calling
    .split on nil raised NoMethodError: undefined method 'split' for nil:NilClass.
    
    This commit:
    - Fails with Failure::Unreachable if the /tree response is nil.
    - Uses safe navigation to extract the redirect destination from the Location header.
    - Preserves the existing login detection flow and routes missing or non-matching
      redirects to Failure::UnexpectedReply without crashing.
