    Keep AutoSystemInfo working for case-variant stdapi
    
    The case-insensitive extension dedup keeps the operator's spelling, so
    an "AutoLoadExtensions Stdapi" survives rather than the auto-added
    lowercase "stdapi". The bootstrap load loop then compared
    `extension == 'stdapi'` case-sensitively, so load_session_info was
    skipped and AutoSystemInfo collected nothing for that input, even
    though the extension itself loaded fine (load lowercases internally).
    
    Compare the extension name case-insensitively at the load site so
    system info is collected for any casing of stdapi. Adds a bootstrap
    regression spec asserting load_session_info fires for a "Stdapi" entry
    with AutoSystemInfo enabled.

    Change the ENABLE_MEM_PROTECT OptBool default in modules/post/windows/manage/dell_memory_protect.rb from the string 'false' to the boolean false.
    
    Because non-empty strings are truthy in Ruby, reading datastore['ENABLE_MEM_PROTECT'] before option validation normalizes it caused datastore['ENABLE_MEM_PROTECT'] ? '1' : '0' to evaluate to '1', enabling memory protection even though the declared default is false.
